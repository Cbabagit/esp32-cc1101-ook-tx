# Windows player MIDI 键盘集成

原播放器新增“MIDI 键盘 · 自定义映射”页签。CSV／视频播放继续在原页签使用。

## 开始使用
1. 运行 lightstick-player.exe，打开 MIDI 页签。
2. 输入设备选 Minilab3 0，点“连接键盘”。此时只学习与预览，不发射。
3. 输出串口选 COM10，在播放器页保持 USB 串口模式，点“启动场控”。启动会停止 CSV／视频播放并释放播放器串口，MIDI 场控独占板端引擎。
4. 需要回到 CSV 播放时，先点“停止场控”，再到播放器页重新连接。
5. “黑场”锁定输出为灭，“恢复”显式解除。重新连接会保留板端黑场锁定；不会自动点亮。

## 默认 MiniLab 3 映射
- 第1通道旋钮1 CC74：色相。
- 旋钮2 CC71：饱和度；旋钮3 CC76：亮度。
- 推子1 CC82：主亮度。
- 音符48–72：色轮，按键力度控制亮度。琴键松开不自动熄灭。

CC74／71／76／82是本次真实键盘采集结果。音符48–72是可编辑的默认范围。

## 自定义面板
选择一行，在右侧修改后点“应用到选中映射”。支持新增、复制、删除、上下移动。规则按列表顺序处理，同一输入可以控制多个参数；黑场动作终止本次处理并清除待发动作。

输入可选 CC、按键按下／松开、弯音、通道压力、复音压力、程序切换。通道可以选全部或1–16；CC／音符编号填-1表示全部。弯音输入范围通常为-8192至8191；其他输入通常为0–127。琴键色轮的输入范围使用音符编号。

控制目标包含色相、饱和度、亮度、主亮度、RGB分量、闪烁档位、琴键色轮、固定色、调色板脉冲、黑场、解除黑场、保持切换、调用场景。连续参数可设输入／输出范围、反向、Gamma、死区和相对编码步长。输出范围0–1，闪烁档位换算为0–3。色相首尾循环；RGB最终量化为各16级。

动作可选每条消息、大于阈值、上升沿、下降沿。用于CC按钮时建议选择上升沿，避免按下／松开重复触发。Note On力度0按Note Off处理；松开动作若力度为0，应选择“每条消息”，并限定音符编号。琴键的上升沿会在松开后重新允许触发。

“学习选中控件”捕获下一次有效输入并填写类型、通道和编号。该条输入只学习、不触发。色轮保留音符范围映射，编号仍为全部。编辑或删除规则会取消正在进行的学习。

“当前灯态存为场景”保存色相、饱和度、亮度、主亮度和闪烁档位；使用“调用场景”映射绑定琴键或垫子。黑场和保持开关不属于场景。

点“保存配置”写入 %APPDATA%/lightstick-player/midi-mapping.json，下次自动加载。导入／导出为JSON，最多256条规则。例子位于 examples/minilab3-mapping.json。导入后仍需保存配置才能跨启动保留。输出设置只能在停止场控后修改。

## 输出与验证边界
使用已烧录的0.5.3-midi2固件，当前MIDI场控输出支持USB串口。全局9槽同色，不提供区域独立控制；CSV原有USB／UDP／BLE功能保留。SysEx、时钟和MIDI 2.0不参与映射。

D8帧数可选1／2／3／6，推送上限1–200次/秒；真实速率受串口RPC与空口帧耗时限制。连续状态覆盖为最新值，动作队列最多8条，超限会丢弃超额动作并计数，通信错误会停止场控，动作不盲目重发。停止调度不保证接收棒熄灭，需要熄灭时先黑场再停止。

本次已验证源码界面、映射模型、原播放器协议／传输／视频全屏，以及真实MiniLab 3输入端口打开与COM10串口交接、合成CC输入后的板端发射完成、黑场、恢复和释放。用户前一轮的实际键盘输入采集仍有效；本轮新增界面联调使用合成CC，不声称重新进行了真实按键或光棒接收验证。

文件夹版包含Python与界面运行库，不要求用户安装Python；视频功能仍需要本机VLC。必须完整解压压缩包，保留EXE旁边的 _internal 文件夹，不能只复制EXE。

2026-10-07启动修复：交付格式改为文件夹版，避开单文件启动时创建临时解包目录的步骤。若之前遇到“could not create temporary directory”，请使用新版完整压缩包。构建默认输出文件夹版；仅在临时目录正常时可手动选择 --onefile。

## MIDI2 平滑与快速输入修复（2026-10-07）

窗口标题为“MIDI2 平滑控制版”，需与已烧录的0.5.3-midi2固件配套。旧映射文件自动补齐新设置，不删除自定义规则。

连续目标以8bit RGB进入板端，板端根据时间插值，发送前才量化为D8的4bit RGB。平滑过渡默认为100毫秒，0表示立即切换，范围0–2000毫秒。过渡没有旧指令队列；持续输入会调整当前过渡的目标，停手后收敛到最后值。8bit是内部目标精度，光棒收到的仍只有16级/分量。

“逐帧冗余数”仍可选1／2／3／6，现在将冗余拆成完整单帧，新目标在帧边界取代旧目标。设6不会再强制等待整个6帧爆发才更新。额外补发默认2帧，在目标稳定、停手后再次发送最终颜色；补发次数有限。普通停止、黑场、租约到期都等待当前完整帧结束，只有显式ABORT是立即中断。

发射会话内复用RMT及无线配置，减少重复初始化。串口读取有时间／字节预算，避免洪泛阻塞调度。输入过快时连续状态合并为最新目标；脉冲动作超限会丢弃超额动作并计数，继续维持场控。界面显示完整帧、合并、中断、错误及丢弃动作统计，便于区分发送端错误与接收端漏收。

符号宽度默认250微秒，D8净空口耗时130.25毫秒，约7次状态更新/秒。200微秒档净空口104.2毫秒，约9次/秒；当前代码原有注释记载200档曾可解码，但本轮仅验证发射完成，仍需用你的光棒确认，默认保持250。频率433.920MHz及功率-30dBm保持不变。

建议先使用：逐帧冗余1、推送上限50、过渡100、符号250、停手补发2。较慢的渐变可尝试过渡300–1000；这不会增加无线帧率。真正连续的高精度丝滑需要接收棒提供本地插值/渐变或更快的兼容协议，无法仅靠提高MIDI或串口频率保证。
